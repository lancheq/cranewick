# DECISIONS.md — 架构决策与锁定约束

> **本文件记录"已经拍板、不得随意改动"的决策。**
> 每条决策有唯一 ID，可被 `agent.md`、`ART_BIBLE.md`、`CHANGELOG.md` 与代码注释交叉引用。
>
> 格式：`ID · 决策内容 · 理由 · 影响范围 · 若必须改动则…`
> 涉及**数值自洽约束**的条目（标 🔒），改动任一参数后必须重算并更新本表。

## A. 工程与流程决策

### A-01 · 无构建器，用 importmap 直跑 ES Module
- **理由**：项目要求"双击/一条命令就能看"，预览页需单文件自包含、可随时打开。
- **影响**：所有代码必须是浏览器可直接执行的 ESM；不得引入需要编译的语言/语法。
- 🔒 **若必须引入构建**：需同时提供 `dist/` 与源码两条路径，且预览页不得依赖构建产物。

### A-02 · three.js 本地化到 `vendor/`，零 CDN 依赖
- **理由**：离线可跑是硬要求；CDN 失效会直接导致整页打不开。
- **影响**：`vendor/` 内文件**禁止修改**；升级版本时整目录替换并重跑一次预览自检。
- **坑**：addon 必须按子目录归位（`jsm/controls/` `jsm/postprocessing/` `jsm/shaders/` …），
  平铺会导致 `three/addons/*` 全部 404 且**页面无任何报错**，只停在加载遮罩上。

### A-03 · 阶段 2 逐资产串行拍板，未拍板不进入下一资产
- **理由**：用户明确要求"逐个建模展示拍板之后再生成完整版"。
- **影响**：不得提前做全场景合成；每个资产必须有独立预览页与拍板清单。

### A-04 · 每个资产一个预览页，共用 `src/core/viewer.js`
- 🔒 **理由**：预览页与最终场景必须共用材质/光照/雾，否则"预览所见 ≠ 最终所得"，
  逐个拍板就失去意义。
- **影响**：禁止任何资产自建灯光或自建材质管线。

### A-05 · 造型相关的随机必须走固定种子
- **理由**：`Math.random()` 会让每次刷新造型变化，无法拍板、无法复现。
- **影响**：`src/core/rand.js` 的 `mulberry32`；仅粒子/水面允许非造型用途的随机。

### A-06 · 全量过程记录，可溯源（2026-09-14 用户明确要求）
- **理由**：用户要求"过程记录文件都需要保存可以溯源"。
- **影响**：四份记录文件必须与代码同轮更新，不得事后补——
  | 文件 | 记什么 |
  |---|---|
  `docs/CHANGELOG.md` | 逐轮变更：用户原话 → 根因 → 改法 → 文件 → 可复现证据 |
  `docs/DECISIONS.md` | 本文件：锁定决策与自洽约束 |
  `docs/ART_BIBLE.md` | 风格宪法：色板/材质/造型/尺度/物理契约 |
  `agent.md` §11–§15 | 每轮决议摘要 + 反模式清单 |
- **证据要求**：必须是**可复现的**（具体命令 + 数值，或核验工具入口），
  不接受"感觉好了"这类主观描述。

### A-07 · 核验工具必须先复位积分状态
- **理由**：实测踩到过——`__trace` 未复位时测的是"续着上一段在跑"的曲线，
  同一时间点两次测量结果不同，不可复现。
- **影响**：任何采样/核验工具在开始前必须 `reset()` 所有积分型状态
  （浮力、弹簧、粒子、平滑器、差分基准）。

## B. 渲染决策

### B-01 · 单一 toon 材质管线
- 🔒 **理由**：风格化风格统一的根本。只要有一个物体走写实 PBR，统一感立刻崩。

### B-02 · 受限色域（调色板唯一取色来源）
- 🔒 **理由**：风格化的本质是**受限制**，不是多。
- **影响**：资产文件内**禁止十六进制字面量**（例外：程序化贴图的画布绘制，见 B-07）。

### B-03 · 单一光照与雾，全局共享
- 🔒 **影响**：单体预览页也必须用同一个 `createStage()`。

### B-04 · 描边只给"英雄剪影"，且细长构件一律免描边
- **理由**：① 全量描边让 draw call 翻倍；② 描边是**绝对宽度**，对半径 0.09 m 的管路
  0.022 m 外扩 = 25% ⇒ 整根被黑壳包住，读成"粗黑管"。
- **判据**：用**构件自身截面尺寸**（`tagThinMembers`），**不能用包围球半径**
  （细长杆件包围球很大但截面极小）。
- **实测**：飞艇标记 460 件 ⇒ 描边 92→23，draw call **1473→963（−35%）**。

### B-05 · 超大平滑曲面不接收阴影
- **理由**：62 m 长曲面自接收阴影，4096 shadowMap + normalBias 0.08 仍压不住痤疮。
- **影响**：该物体仍向外投影。气囊是当前唯一适用对象。

### B-06 · 带贴图材质的 `color` 必须给白
- **理由**：`color × map` 是**相乘**关系，颜色写两遍会被二次压黑。

### B-07 · 非必要不写自定义 GLSL，优先程序化 CanvasTexture
- **理由**：自定义 `ShaderMaterial` 编译失败会**整页挂掉**，且 three 报的错位置完全误导
  （实测报出 `Cannot read properties of undefined (reading 'value')`）。
- **例外**：水面（Gerstner 波）必须用 GLSL，已单独验证。

## C. 几何与装配决策

### C-01 · 端点驱动装配，禁止手调 transform
- 🔒 **理由**：多零件机械件"悬空不连接"的根因 100% 是手调 `position + rotation`。
- **影响**：一律用 `strutBetween(p0, p1)`；曲面接点用型线函数取真值
  （`envLowerY` / `envUpperY` / `envPoint`）。

### C-02 · 型线辅助函数返回**绝对坐标**；偏移写进几何，组的变换保持单位
- 🔒 **理由**：混用"组偏移 + 绝对辅助函数"会二次叠加 ⇒ 零件整体浮空一个固定高度。
- **影响**：`shellGeo.translate()` 而非 `group.position.y =`。

### C-03 · 几何变换顺序：**先旋转，后平移**
- 🔒 **理由**：顺序颠倒时旋转会把平移量转到别的轴上（v4 的"龙骨没对齐"就是此因）。
- **实现**：`geo.rotateZ(-π/2)` **再** `geo.translate(0, ENV_C, 0)`；`mesh.rotation` 保持单位。

### C-04 · 环形分布的收束相位必须与环件位置对齐
- 🔒 **实现**：`pinch = f(cos(2π(x + ENV_HL) / RIB_SPACING))`。
- **坑**：写成 `cos(2πx/SPACING)` 时，若 `半长/间距` 是半整数（本项目 5.5），
  环件正落在鼓包上、收束跑到两根环之间。

### C-05 · 转动件的支撑结构必须避开扫掠圆
- 🔒 **判据**：支撑与**转轴轴心**的**径向距离** > 转动半径 + 余量。
  注意是径向距离，不是"在不在同一个轴向位置"。
- **实现**：纵向长梁抬到扫掠圆之外当主承力件；短舱用垂直于长梁的短吊架，
  与转动面**错开一个轴向距离**。

### C-06 · 舵面的厚度方向必须与转轴垂直；铰点在安定面后缘
- 🔒 **理由**：厚度方向不对 ⇒ 绕自身平面内的轴自转 ⇒ **视觉上完全不动**，极难发现。
- **对照**：方向舵 (厚沿 Z) 绕 Y；升降舵 (厚沿 Y) 绕 Z。
- **自检**：把舵面摆到 +20° 与 −20° 各截一张图，确认有可见形状变化。

### C-07 · 齿轮传动：节圆相切、模数统一、两端可读
- 🔒 **理由**：孤立齿轮"意义不明"——传动必须能看出谁在推、推给谁。
- **实现**：中心距 = 两节圆半径之和；`节圆半径 = 模数 × 齿数 / 2`；
  传动比 `ω₁=1, ω₂=−z₁/z₂, ω₃=−z₂/z₃·ω₂`；每轴配轴承座，长轴每 ~4 m 一个吊挂轴承。
- **尺度**：模数决定观感，m=0.09 → 24T 半径 1.08 m（本项目取值）。

## D. 物理决策

### D-01 · 浮力自洽（🔒 改动任一参数必须重算全表）
- 公式：`d = m / (ρ · A_wp)`，ρ = 1.025 t/m³
- 当前：`m = 430 t`、`A_wp = 150 m²` ⇒ `d = 2.80 m`（设计吃水 2.8 m ✓）
- 两条**观感约束**同时必须满足：
  1. 非浮体最低点高于水线 ⇒ 吊舱保持干燥（当前余量 2.4 m）
  2. **浸没率 ≈ 70%**（`d / D = 2.8 / 4.0`）⇒ 一眼看得出"浮着"而不是"沉了"
- 相关派生量（一并锁定）：`pontoonCenterY = −23.3`、`keelY = −25.3`、`FLOAT_Y = 22.5`

### D-02 · 浮沉用欠阻尼弹簧，平衡位置是吃水
- `y'' + 2ζω·y' + ω²·y = 0`，`ω = √(g/d) = 1.75 rad/s`，`ζ = 0.22` ⇒ 周期 3.59 s
- 衰减：每周期振幅 ×0.27，3 个周期后残余 < 5%

### D-03 · 撞击后的姿态用弹簧**回正**，不是永久偏转
- `θ'' + 2ζωθ' + ω²θ = 0`，`θ(0)=θ0`、`θ'(0)=v0`，**平衡位置恒为 0**
- 俯仰：θ0 = +2.4°（进场抬头）、v0 = −11 °/s（水冲击）⇒ 峰值 −4.2° → 回正
- 横滚：独立弹簧（θ0 = +0.9°、v0 = −3.2）
- **反例**：把 trim 当永久静态前倾 ⇒ 物体永远歪着（v3 的错误）

### D-04 · 有朝向的物理事件禁止同心圆环
- 🔒 船/车/落下物入水是**方向性**的：船首水墙 + 两侧翼浪 + 横向推移浪丘（脊线平行船身）
  + 前向船首波 + 朝前偏置扇形粒子
- "同心圆环向四周扩散"是**石子落水**模型，物理上错

### D-05 · 瞬态特效"被过程激起"，不播固定动画
- 🔒 **实现**：`trigger({scale})` 主爆 + `pulse(strength)` 只要主体还在动就每帧补喷；
  强度取自**主体自身的速率**（如浮力弹簧的 `v`）
- **理由**：一次性 trigger 后按固定时间轴播完 ⇒ 僵硬、与主体动作不同步

### D-06 · 帧率无关 + 热路径零分配
- 🔒 **积分型物理**用**定步长子步**：累计推进时间严格等于真实帧间隔（上限 0.25 s）
- 🔒 **运动学量**按**绝对时间**取值（与帧率无关）
- 🔒 **热路径零分配**：临时向量提模块作用域（GC 停顿表现为"卡顿几帧"）
- **跨关键帧只推进落后段**：如跨触水帧只推进 `max(0, t − max(t0, T_TOUCH))`

### D-07 · 大长径比物体的波面跟随必须低通 + 强衰减
- 🔒 **理由**：把波高直接加到位置上 ⇒ ① 与浮力弹簧**重复计数**；
  ② 波频（0.33–0.72 Hz）与弹簧频（0.28 Hz）叠加产生**拍频** ⇒ 观感不流畅
- **实现**：一阶滤波 τ = 1.2 s，跟随系数 0.12（86 m 长的艇不会跟着 3–14 m 的波起伏）

### D-08 · 最终位姿过一层帧率无关的一阶滤波
- **理由**：冲击是脉冲式的 ⇒ 位姿**速度不连续**，位移连续但观感生硬
- **实现**：τ = 0.05 s 的指数滤波；延迟 ≈ 6 cm，不可见
- **实测**：触水帧速度突变 **0.63 → 0.078 m/s（−88%）**

# F. 风格与尺度宪法（v8 · 2026-09-15 用户明确重新定调）

> 用户原话：

> 比如说街上的汽车可以改成蒸汽机驱动低空悬浮；整体比例尺也有调整一下，飞艇原模型不变但是

> 公园广场等单独建筑在最终模型中可以进行素材复用」

## F-01 风格总纲（🔒 最高约束，与调色板同级）

**蒸汽朋克 = 蒸汽机 / 工业革命机械 构建出来的近未来科幻体系。**

| 是 | 不是 |
|---|---|
结构外露：看得见动力从哪来、传给谁 | 装饰性尖拱、扶壁、雉堞 |
机械可动：齿轮 / 活塞 / 曲柄 / 阀门 / 压力表 / 飞轮 | 阴郁低饱和、烛光、雨雾、墓地感 |
材质：黄铜 + 铸铁 + 铜管 + 铆接钢板 + 压力容器 | 纯石砌体量（可以有石基，但不能只有石） |
能量可见：蒸汽 / 压力 / 传动轴 / 排烟 | 哥特尖塔、玫瑰窗、彩玻 |

**判据（做任何一个部件前先自问）**：
1. 这个部件**在动吗**？不动的话，它的动力**看得见是从哪来的**吗？
2. 换掉材质后它还成立吗？——若换成木头/石头也成立，说明它没有机械特征，不合格。
3. 它有没有 **① 铆接/螺栓 ② 管路/压力表 ③ 传动件** 三者之一？

## F-04 运河口径（威尼斯参考）

- 河道**窄而深**（宽 18 / 深 3），两侧**石砌河堤**（花岗岩块 + 压顶 + 系船环）
- 河堤上必须出现：**石阶入水口**、**下水道出水口拱**、**系船柱**、**拴船桩**
- 允许**跨巷小桥**（人行、无台阶）与**建筑直接临水**（墙基浸水）
- 船：小艇 / 平底货船（后续资产）

## F-05 桥：通车路桥（🔒）

- 必须有**车行道 + 人行道 + 栏杆**，不能是实心墙
- 主体结构用**外露桁架 / 板梁 + 铆接**，看得穿
- 起桥动力**外露**：液压蓄能器 / 齿轮组 / 配重 + 钢索
- 塔（若保留）必须是**机械塔**：鼓形机舱 + 铆接钢帽 + 压力穹顶 + 排烟管，**不许尖塔**

## F-06 城市建筑套件（🔒 必须可复用）

五类建筑**各自独立成组件**，签名统一，供全场景按需布置与实例化：

```js
buildResidential(o)  // 居民楼（联排/多层公寓）
buildVilla(o)        // 小别墅（含玻璃温室 + 铜制风向标）
buildFactory(o)      // 工厂（厂房 + 高烟囱 + 外露锅炉/管廊 + 冷却塔 + 龙门吊）
buildPark(o)         // 公园（草坪 + 铸铁凉亭 + 铜管喷泉 + 长椅 + 树）
buildPlaza(o)        // 广场（铺装 + 中央压力机式纪念塔 + 街灯 + 花坛）
```

约定：
- 每类接受 `{ w, d, floors, seed, materials }` 之类的参数，**同一份代码能出多种变体**
- 每类返回 `THREE.Group`，`userData.parts` 暴露可动件与可挂点（灯位/招牌位/管接口）
- 外部只允许通过参数与 `parts` 交互，不得依赖内部网格命名
- **禁止**在组件内写死世界坐标（位置由调用方给）
